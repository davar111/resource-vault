# Принятые решения

Обновлено: 2026-02-23

## 2026-02-22

1. Для модалок использовать единый helper доступности.
- Решение: `src/ui/dialogA11y.js` + подключение в ключевых местах.
- Причина: устранение дублирования и стабильный focus trap.

2. Для карточек использовать батч-рендер через `DocumentFragment`.
- Решение: `renderGrid` пишет DOM пакетно через `replaceChildren`.
- Причина: уменьшение лишних перерисовок на больших списках.

3. Для меню коллекций/фильтров использовать общий toggle-helper.
- Решение: `bindCollectionMenuToggle(...)`.
- Причина: убрать дубли и упростить поддержку.

4. Разбить `src/styles.css` на модульные части без изменения порядка правил.
- Решение: агрегатор `src/styles.css` + модули `src/styles/*.css`.
- Причина: снизить сложность сопровождения и упростить навигацию.

5. Переименовать CSS-модули в доменные имена.
- Решение: `tokens-base.css`, `layout-shell.css`, `components-ui.css`, `responsive-breakpoints.css`.
- Причина: быстрее ориентироваться по назначению слоя стилей.

6. Редизайн выполнять поэтапно: сначала токены, потом layout, потом карточки.
- Решение: изменения разделены на 3 шага без смешивания с бизнес-логикой.
- Причина: минимизировать риск регрессий и ускорить проверку результатов.

7. На шаге 3 для карточек использовать композицию, близкую к эталону.
- Решение: превью-контентная структура через CSS (верхний preview и внутренние отступы контентной части), унификация бейджей и кнопок поверх превью.
- Причина: визуально приблизить текущую разметку к `vault-redesign.html` без изменения JS/DOM.

8. Палитру привести к нейтральной во всех ключевых элементах управления.
- Решение: обновлены акцентные и вспомогательные цвета (`dot/tag/select arrows/new badge`) в `src/styles/tokens-base.css`, `src/styles/layout-shell.css`, `src/styles/responsive-breakpoints.css`.
- Причина: консистентный визуальный язык без случайных старых оттенков.

9. Для максимально близкого визуала использовать иконки эталона без изменения логики приложения.
- Решение: иконки навигации/поиска/фильтров и стиль pills перенесены из `vault-redesign.html` через CSS/HTML, а перевод обновляет только label-спаны.
- Причина: сохранить функциональность (`id`/события) и получить внешний вид "как в файле".

10. Для полного визуального переноса добавить отдельный финальный CSS-слой поверх модульной системы.
- Решение: создан `src/styles/redesign-exact.css` и подключен последним в `src/styles.css`.
- Причина: быстро применить "как есть" палитру/типографику/иконки из эталона без рефакторинга логики.

## 2026-02-23

11. Для стабильности первого рендера не итерироваться по `.options` у скрытого `input`.
- Решение: в `applyI18n()` добавлена проверка `tagName === "SELECT"` для `inputAddSource`.
- Причина: устранить рантайм-краш и пустой экран на старте.

12. Парсинг URL в add-flow запускать только по явному действию пользователя.
- Решение: убран `debouncedAddParse` на каждый ввод; parse остаётся по `Enter`/кнопке `Далее`/preset URL.
- Причина: убрать лаги и лишние сетевые запросы.

13. Smart-search перевести на popup-режим по эталону, а старую chips-строку скрыть.
- Решение: добавлен `#searchPanel` (чипы + preview результатов + count + keyboard UX), legacy `chipsBar` отключён.
- Причина: привести UX поиска к целевому сценарию и сократить визуальный шум.

14. Для безопасности принимать и рендерить только `http/https` URL.
- Решение: добавлен `toHttpUrl()` в `src/filter.js`; применён в add-flow/import/migrate/search/open/card-href.
- Причина: закрыть XSS/unsafe-link сценарии и исключить `javascript:`/`data:` из UI потока.

15. Для shared-режима показывать действия изменения только владельцу ссылки.
- Решение: в `src/useLinks.js` добавлен `ownerId` из `user_id`, в `src/ui.js` введён `canManageItem(...)`, в `src/main.js` добавлены проверки `canMutateItem(...)`.
- Причина: не провоцировать RLS-ошибки и сохранить корректную read-only модель для приглашённых.

16. Единым источником схемы сделать `supabase.sql`.
- Решение: в `supabase.sql` добавлена таблица `public.users` + RLS политики; `AI_ONBOARDING_SETUP.md` переключён на `supabase.sql`.
- Причина: убрать рассинхрон между onboarding-функцией и фактической схемой БД.

17. Режим `Space` реализовать как отдельный экран внутри текущего `activeCollectionId`.
- Решение: добавлен `activeCollectionId = "space"` с отдельным контейнером `#spaceView`, рендером одной карточки, swipe/open/archive действиями и прогрессом.
- Причина: внедрить новый сценарий «разбора ссылок» без ломки существующей сетки и without-refactor остальных режимов.

18. Стрик `Space` хранить только в runtime-состоянии.
- Решение: счётчики (`dailyDone`, `streakDays`, `lastActionDate`, `lastStreakDate`) ведутся в `state.space` без `localStorage`.
- Причина: прямое требование пользователя: не сохранять стрик локально.

19. Перенести стрик `Space` из runtime в Supabase для авторизованного пользователя.
- Решение: добавлена таблица `public.user_space_stats` + RLS; в клиенте подключён `src/useSpaceStats.js` и upsert после `open/archive` в Space.
- Причина: обеспечить сохранение серии между сессиями и устройствами без использования `localStorage`.
## 2026-02-26

20. Для AI-онбординга использовать гибридную модель: динамический `chat_turn` + локальный fallback-дерево вопросов.
- Решение: клиент сначала запрашивает `action: "chat_turn"` (таймаут 8с), при ошибке или невалидном ответе переключается на `resolveNextQuestion`.
- Причина: сохранить устойчивость UX при сетевых/LLM-сбоях и не блокировать завершение онбординга.

21. Кнопку `Назад` скрывать только в AI-режиме.
- Решение: back-nav доступен в fallback-дереве, отключен при динамических AI-вопросах.
- Причина: в AI-диалоге вопрос не детерминирован локальным графом, возврат может ломать контекст.

22. Bot-сообщения онбординга показывать через typing-индикатор.
- Решение: `appendMessageWithTyping` с `●●●` (600-900ms), затем подмена на итоговый текст.
- Причина: улучшить ощущение живого диалога без изменения структуры модального окна.
23. Для ошибок Edge Function в онбординге не выводить сырой backend JSON пользователю.
- Решение: в `src/Onboarding.js` для 401/403 и невалидного токена показывать локализованное auth-сообщение, остальные ошибки парсить через `message/error`.
- Причина: убрать тех-шум (`Invalid JWT`) из UX и дать понятный шаг восстановления.

24. Проверять формат access token даже при непросроченной локальной сессии.
- Решение: в `src/supabase.js` `ensureValidSession()` возвращает кэш-сессию только если token не истёк и выглядит как валидный JWT с `sub`; иначе выполняется refresh/сброс.
- Причина: предотвратить отправку битого токена в Edge Function.
25. В AI-онбординге поддерживать два канала ввода ответа: quick chips + free text.
- Решение: в `src/Onboarding.js` включено поле ввода на шаге вопросов, добавлены `Send` и `Enter` обработчики, поток отправки унифицирован через `submitAnswer`.
- Причина: сделать диалог ближе к обычному чату с ИИ без изменений разметки `index.html`.

26. После auth-error в финализации не показывать успешный result-copy.
- Решение: введён флаг `authRequired`; в `renderResult` отображается `Sign in required` + auth-сообщение, успешные строки и карточки не рендерятся.
- Причина: устранить противоречивый UX (ошибка авторизации + одновременно "профиль готов").
27. Для расследования качества AI-диалога добавить явную диагностическую телеметрию chat_turn.
- Решение: в `supabase/functions/ai-onboarding/index.ts` возвращается `debug` (trace_id, used_llm, parsed_ok, fallback_question/options, done_reason) и дублируется в `console.log`.
- Причина: отделить проблемы ключа/провайдера/парсинга JSON от поведения fallback без догадок.

28. Временный клиентский debug-режим включён по умолчанию для chat_turn.
- Решение: `src/Onboarding.js` отправляет `debug: true` и показывает `diag: ...` в status-line.
- Причина: мгновенная проверка в UI без открытия devtools у конечного пользователя.
29. В chat_turn fallback-логике опции не должны искажать семантику вопроса.
- Решение: parsed-options теперь берутся только если реально пришли от модели; иначе используются options из fallback-вопроса.
- Причина: устранить конфликт вида "вопрос про цель" + "варианты уровня".

30. Защита от повтора одинакового вопроса подряд в fallback.
- Решение: если следующий вопрос совпадает с предыдущим, выбирается альтернативный из fallback-списка.
- Причина: убрать зацикливание UX при недоступном LLM.

31. Временно отключить вход в AI-онбординг через UI-кнопку.
- Решение: в `index.html` удалена кнопка `#btnAiOnboarding`, в `src/main.js` флаг `ENABLE_AI_ONBOARDING` переведен в `false`.
- Причина: прямое продуктовое решение убрать AI-кнопку без изменения остального интерфейса и логики приложения.
